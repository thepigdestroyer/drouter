# Client Leaks, Response Header, External Origin, and Seed Derivation Audit

## Scope and Methodology

1. Built an isolated production build in `/private/var/folders/bz/mcd91b7943dgjb_pkmry9wtc0000gn/T/opencode/scratch-23` (`npx next build` on Next.js 16.4.3 / Turbopack) and scanned 36 files in `.next/static/**`, 12 files in `public/**`, and 61 prerendered HTML and RSC payload files in `.next/server/app/**`.
2. Loaded `.env.local` in memory and compared every full value, stripped-`0x` hex value, `MONGODB_URI` credential/host component, and `CREDITS_ISSUER_RSA_PQ` prime factor (`p`, `q`) against all browser-downloadable build artifacts and live responses. No secret values are printed in this report.
3. Queried every page (`/`, `/about`, `/argon`, `/audit`, `/explain`, `/login`, `/network`) and GET API route on `https://drouter-demo.vercel.app` (sequential GET requests only, no load) to inspect response headers and JSON bodies.
4. Inventoried all external origins in `src/**` and `node_modules/tinfoil` (`tinfoil`, `@tinfoilsh/verifier`, `ehbp`).
5. Audited all server key and seed derivation paths across `src/lib/**` and `src/app/api/**`.

## 2. Production Response Headers and Bodies (`https://drouter-demo.vercel.app`)

### 2.1 Header Audit Across Pages and API Routes

- **Security headers present on all routes**:
  - `strict-transport-security: max-age=63072000; includeSubDomains; preload`
  - `referrer-policy: no-referrer`
  - `x-frame-options: DENY`
  - `x-content-type-options: nosniff`
  - `permissions-policy: camera=(), microphone=(), geolocation=(), browsing-topics=(), interest-cohort=()`
- **Missing or leaking headers**:
  - **Missing `Content-Security-Policy` header**: Neither `next.config.ts` nor `src/proxy.ts` sets a `Content-Security-Policy` header. Without `connect-src 'self'`, client code can contact third-party origins directly from the browser (Finding CL-09).
  - **Missing `poweredByHeader: false` in `next.config.ts`**: While Vercel's edge proxy strips `x-powered-by` in production, self-hosted `next start` responses emit `X-Powered-By: Next.js` unless `poweredByHeader: false` is set in `next.config.ts` (Finding CL-11).
  - **Wildcard `Access-Control-Allow-Origin: *` and `Cache-Control: public, max-age=0, must-revalidate` on stateful JSON routes**: Only `/api/sim/roots` sets `Cache-Control: no-store`. Dynamic routes such as `/api/accountability`, `/api/credits`, `/api/freeze`, `/api/gemini`, `/api/log`, `/api/ohttp`, `/api/threshold`, and `/api/transparency` return `Cache-Control: public, max-age=0, must-revalidate` (Finding CL-10).
  - **Platform routing headers**: Responses include Vercel platform headers `server: Vercel`, `x-vercel-id` (edge + serverless execution region and internal request ID, e.g. `lhr1::iad1::...`), `x-vercel-cache`, and `x-matched-path` (which reveals internal dynamic route templates such as `/api/relay/[relayId]/attestation`).
  - **`GET /api/health` returns `404` on production**: The `/api/health` endpoint is not yet deployed on `https://drouter-demo.vercel.app`.

### 2.2 Secret-Looking Values in Production JSON Bodies

- **`GET /api/accountability`**: Exposes `activeCanaries.<nodeId>.honeytoken` (e.g. `sk-live-drouter-...`, `xprv9s21ZrQH143K-...`) and `activeCanaries.<nodeId>.salt` (64-hex-char pre-commitment salt) for every node in plaintext before any leak has occurred (Finding CL-06).
- **`GET /api/gemini` and `POST /api/gemini`**: Exposes `autonomousRun.stages.stage1.placeholders` (mapping `[[DROUTER_SECRET_1]]` and `[[DROUTER_EMAIL_1]]` back to raw unredacted secrets/PII) and `symmetryMasks[].original` in the HTTP response body (Finding CL-07).
- **`GET /api/threshold` and `POST /api/threshold`**: Returns `reconstructedKeyHex` (the reconstructed threshold master key) and all `n` Shamir shares in the JSON response (Finding CL-05).
- **`GET /api/freeze`**: Lists all users' frozen blob metadata (`blobId`, `sessionIdHex`, `modelId`, `byteLength`, and uncoarsened `createdAt` / `expiresAt` Unix seconds) without authentication, allowing any caller to fetch or `DELETE /api/freeze/[blobId]` any user's frozen session (Finding CL-08).
